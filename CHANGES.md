# 📝 Project Improvements & Changes Summary

This document details all bug fixes, new architectural modules, how to run each component, and real execution metrics for the university Information Retrieval (IR) mini project.

## 🐛 Part 1: Bugs Fixed

| # | Issue Identified | Resolution |
| :--- | :--- | :--- |
| **1** | `app/app.py` used `pd.DataFrame` and `pd.read_csv` without importing `pandas`. | Added `import pandas as pd` at the top of `app/app.py`. |
| **2** | `app/app.py` nested feedback buttons inside the `if st.button("Analyze Sentiment"):` block, which caused feedback UI to reset and disappear immediately on Streamlit rerun. | Refactored with `st.session_state` (`last_analysis`, `show_feedback_correction`) so that feedback and correction forms persist and function reliably across reruns. |
| **3** | `src/train.py` printed *"Building Ensemble Model"* and imported `VotingClassifier` without actually training or saving an ensemble. | Implemented a genuine **Soft-Voting Ensemble** (`VotingClassifier` combining Logistic Regression and Multinomial Naive Bayes via a non-negative feature clamping pipeline). Evaluated and saved as `models/ensemble.joblib`. |
| **4** | Data leakage: duplicate tweet texts existed across Positive/Negative samples, allowing identical text to appear in both train and test splits. | Deduplicated on `clean_text` before splitting (current run: `42,078 -> 35,727` unique samples; 6,351 duplicates removed). Switched to a stratified split (`stratify=y`) preserving class ratios (28,581 train / 7,146 test). |
| **5** | Hard-coded absolute Windows paths (`G:/Dsbda/...`) in `data/generate_tweets.py` and `data/prepare_data.py`. | Created `src/config.py` using `pathlib.Path` relative to the repository root for clean cross-platform path resolution. Removed all hard-coded paths. |
| **6** | `README.md` was outdated (claimed 5,000 features instead of 10,000, didn't reflect the new IR system, didn't specify generated directories). | Overhauled `README.md` to document the full IR and sentiment architecture, 10,000 features, complete directory tree, generated artifacts, and execution instructions. |
| **7** | Punctuation was never removed because the cleanup line was commented out. 40,827 of 64,855 index terms contained punctuation (`game.`, `duty,`, `playstation!`), so query terms often failed to match and TF-IDF features were needlessly fragmented. | `clean_text()` now normalizes punctuation **before** stop-word removal, keeps apostrophes and negation words, converts hashtags to words, and strips URLs/mentions. The rebuilt index has 29,244 clean terms. |
| **8** | Running `python -m src.ir.index` emitted a `runpy` warning because `src/ir/__init__.py` eagerly imported the submodule being executed. | Made package exports lazy via `__getattr__`/`importlib`, so submodule scripts run cleanly. |
| **9** | A fresh clone had no `results/` artifacts and the Streamlit app crashed with an opaque error when models/index were missing. | Regenerated all evaluation outputs and added an artifact check with copy-paste setup commands before the app loads the search engine. |
| **10** | There was no command-line way to analyze sentiment in batch, and no machine-readable sentiment metrics table. | Added `src/sentiment_cli.py` (single, JSON, interactive, and CSV batch modes) and `results/sentiment_metrics.csv` generated by `src/evaluate.py`. |

## 🏗️ Part 2: New Modules & Files Created

### 1. Information Retrieval Core (`src/ir/`)
- **`src/config.py`**: Centralized path registry (`REPO_ROOT`, `DATA_DIR`, `MODELS_DIR`, `RESULTS_DIR`) and algorithm hyperparameters.
- **`src/ir/__init__.py`**: Public exports for the IR module.
- **`src/ir/index.py`**: Pure Python inverted index data structure with term frequencies, document frequencies, document lengths, and positional postings for phrase search. Persisted to `models/ir_index.joblib`.
- **`src/ir/query.py`**: Query preprocessing pipeline ensuring parity with indexing. Supports multi-word free text, Boolean logic (`AND`, `OR`, `NOT`) via Shunting-Yard parsing, and exact phrase queries (`"..."`) via positional postings.
- **`src/ir/ranking.py`**:
  - `BM25Ranker`: Okapi BM25 ($k_1=1.5, b=0.75$) with Robertson-Spärck Jones non-negative IDF.
  - `TFIDFRanker`: Vector Space Model with log-TF weighting ($1 + \ln(\text{tf})$), smooth IDF, and L2 length normalization. Matches `scikit-learn`'s `TfidfVectorizer` + `cosine_similarity` exactly.
  - `RocchioExpander`: Pseudo-relevance feedback query expansion based on top-5 retrieved documents.
- **`src/ir/search.py`**: `SearchEngine` class combining IR ranking, real-time sentiment inference via `SentimentPredictor`, sentiment filtering (`Positive` / `Negative`), entity filtering, and sentiment distribution calculation.
- **`src/ir/evaluate_ir.py`**: Comprehensive IR evaluation benchmark computing Precision@k (k=5, 10, 20), Recall@k, MAP, MRR, nDCG@10, and 11-point interpolated Precision-Recall curves.
- **`src/ir/cli.py`**: Command-line interface with formatted ASCII tables and query metrics.

### 2. Evaluation Data & Artifacts
- **`data/ir_queries.csv`**: 48 curated proxy test queries covering all 32 entities in the dataset.
- **`results/ir_metrics.csv`**: Benchmark metrics comparison table.
- **`results/ir_pr_curve.png`**: 11-point interpolated Precision-Recall curves.
- **`results/ir_metrics_comparison.png`**: Bar chart comparing P@5, P@10, P@20, MAP, MRR, and nDCG@10.

### 3. Automated Test Suite (`tests/`)
- **`tests/test_preprocess.py`**: Text cleaning, negation preservation, lemmatization, and feature clamping.
- **`tests/test_ir_index.py`**: Inverted index building, postings correctness on a toy corpus, and serialization round-trip.
- **`tests/test_ir_query.py`**: Boolean expressions (`AND`, `OR`, `NOT`) and exact phrase queries using positional postings.
- **`tests/test_ir_ranking.py`**: Sklearn mathematical parity verification, BM25 term frequency ordering, length normalization, and Rocchio expansion.
- **`tests/test_ir_metrics.py`**: Verification of P@k, Recall@k, MAP, MRR, and nDCG@10 against hand-computed ground truth.
- **`tests/test_search.py`**: End-to-end `SearchEngine` search, ranking, filtering, and latency verification.

### 4. Sentiment CLI & Metrics (`src/sentiment_cli.py`)
- Single-tweet prediction with model selection (`--model ensemble|logistic_regression|naive_bayes`).
- JSON output (`--json`), interactive prompt, and CSV batch mode (`--file`) with auto-detected text column.
- Handles the bundled headerless dataset and reports accuracy only on Positive/Negative ground-truth rows.
- `src/evaluate.py` now writes `results/sentiment_metrics.csv` (accuracy, macro/weighted precision/recall/F1).

### 5. Interactive Web Interface (`app/app.py`)
- Upgraded Streamlit interface with 3 tabs:
  1. **🔍 Search Tweets (IR Engine)**: Live search with BM25 / TF-IDF, query term highlighting, sentiment badges, query latency, and sentiment distribution bar.
  2. **🧠 Sentiment Analysis**: Single-tweet classifier with working self-learning feedback submission.
  3. **📊 IR & System Evaluation**: Real-time display of benchmark tables, PR curves, sentiment metrics, and confusion matrices.
- Resource caching with `@st.cache_resource` for instant page reloads.
- Clear setup instructions when `models/` artifacts are missing.

## 🚀 How to Run Everything

```bash
# 1. Activate Virtual Environment
source .venv/bin/activate

# 2. Run All Automated Unit Tests (29 tests)
pytest -v

# 3. Train Sentiment Analysis Models (Deduplication + Stratified Split)
python src/train.py

# 4. Evaluate Sentiment Models (Classification Reports & Plots)
python src/evaluate.py

# 5. Build the Inverted Index
python -m src.ir.index

# 6. Run Information Retrieval Benchmark
python -m src.ir.evaluate_ir

# 7. Sentiment Analysis via CLI
python -m src.sentiment_cli "I absolutely love this update!"
python -m src.sentiment_cli "The servers are down again." --model logistic_regression --json
python -m src.sentiment_cli --file data/tweets.csv --output results/sentiment_predictions.csv

# 8. Search via Command-Line Interface (CLI)
python -m src.ir.cli "cyberpunk update" --k 10 --model bm25
python -m src.ir.cli "\"call of duty\"" --k 5
python -m src.ir.cli "ps5 OR playstation" --query-type boolean
python -m src.ir.cli "battlefield" --sentiment Positive --k 5

# 9. Launch Streamlit Web UI
streamlit run app/app.py
```

### 2. Information Retrieval Benchmark (from `python -m src.ir.evaluate_ir`)

*Evaluated over 48 proxy queries across 32 entities from `data/ir_queries.csv`.*
*Relevance Definition: Proxy ground truth where document entity matches the query's target entity.*

| Metric | TF-IDF (Cosine) | BM25 | BM25 + Rocchio |
| :--- | :---: | :---: | :---: |
| **Precision@5** | 0.7792 | **0.8708** | **0.8708** |
| **Precision@10** | 0.7896 | **0.8771** | 0.8458 |
| **Precision@20** | **0.8000** | **0.8708** | 0.8135 |
| **Recall@10** | 0.0034 | **0.0038** | 0.0037 |
| **Mean Average Precision (MAP)** | 0.7025 | **0.7787** | 0.6409 |
| **Mean Reciprocal Rank (MRR)** | 0.8594 | **0.9010** | 0.8815 |
| **nDCG@10** | 0.7943 | **0.8777** | 0.8516 |
| **Average Ranking Latency** | 2.29 ms | **2.04 ms** | 6.20 ms |

**Analysis:**
- **Okapi BM25** outperforms TF-IDF Cosine on the main ranking metrics (MAP **0.7787** vs 0.7025, MRR **0.9010** vs 0.8594, nDCG@10 **0.8777** vs 0.7943).
- **Rocchio Query Expansion** keeps top-5 precision but adds broad terms at deeper ranks, reducing MAP.
- Ranking latency is measured with the index already loaded and excludes sentiment inference. A warm end-to-end sentiment-aware search adds a few milliseconds per returned tweet (the first prediction has a one-time NLTK/VADER cold start).
